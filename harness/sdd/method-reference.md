# Guía metodológica aplicada a Registro

**Fuente**: «Apunte SDD Compatible», documento privado facilitado por el usuario.
La URL corporativa se omite de la entrega pública; el documento original conserva su acceso privado.
Leído mediante el conector de SharePoint el 2026-10-15; última modificación informada
por el servicio: 2026-10-15. Esta nota resume cómo se aplica, sin sustituir al apunte.

- Constitution conserva el gobierno transversal; no se regenera por funcionalidad.
- Specify contiene contexto, qué y por qué, requisitos, aceptación, límites y exclusiones.
- Plan decide cómo implementar sobre el sistema existente, con decisiones justificadas.
- Tasks produce unidades atómicas, verificables, trazables, ejecutables y con artefactos.
- Implementation sigue las tareas, la Constitución y TDD; las pruebas y evidencias se registran.
- Los documentos de resultado son la fuente de verdad; el prompt conserva la intención.
- La revisión humana continúa siendo necesaria. El usuario autorizó el 2026-10-15
  ejecutar este ciclo sin aprobaciones intermedias y revisar todo al finalizar.
  No se registra esa autorización como aprobación humana de los artefactos producidos.

Este es un trabajo sobre la base existente de login. Se recuperan sus reglas y componentes
antes de ampliar la aplicación. El ciclo no incluye publicar, enviar mensajes, crear tickets,
hacer push ni abrir un PR por sí mismo. Tras la revisión, el usuario autorizó explícitamente
commit y push a su rama del fork el 2026-10-16; el PR permanece como paso posterior.
